# 内容查询 Skill

## 何时使用
用户想看：某店铺的**探店笔记**、某达人的**笔记**、某店铺的**网友评价**。

## 工具选择
| 用户需求 | 工具 | 前置 |
|---|---|---|
| 某店铺的探店笔记 | `queryShopBlogs(shopId)` | 需 shopId（shop 技能获取） |
| 某达人的探店笔记 | `queryUserBlogs(userId)` | 需知道 userId |
| 某店铺的网友评价 | `queryShopComments(shopId)` | 需 shopId（shop 技能获取） |

## 流程
1. 查店铺笔记/评价需要 shopId：**本技能不含店铺搜索工具**（搜索属 shop 技能）。若消息上下文已有目标店铺的 shopId（如上一轮查过），直接使用；否则由 Planner 规划的 **shop** 技能获取——Planner 应把 shop 与 content 一并选入 plan.skills。若运行时无 shopId 且无搜索工具可用，说明规划遗漏，应触发 replan 让 Planner 补 shop。
2. 按上表调用对应工具。
3. 结果为空 → 如实说"暂无笔记/评价"，不编造——编一条假评价或假攻略，用户比对真实内容后会彻底失去信任。

## 护栏
- 不向用户暴露 shopId/userId 等内部 ID（内部标识，用户看到只会困惑）。
- 笔记/评价中的他人信息不可用于猜身份。
- 写评论/点赞属写操作，需用户确认。

## 回答规则（Answer 阶段）
- **评价/笔记类信息尽量完整呈现**：列表全量列出（评价内容、评分、点赞、时间），不要只挑 2-3 条或过度精简——用户要完整信息（数据已全量提供）。
- 单条评价用「评分 + 要点 + 来源」简洁呈现；店铺整体口碑用「均分 + 条数 + 印象概括」。
- 评价/笔记数据一律来自工具结果，**禁止编造评分、内容或"网友都说好"类无依据概括**；空结果如实说"暂无"。
- 若回答同时提到店铺，涉及店铺处按 shop 技能规则输出 `[[id]]` 卡片占位符。
