# 店铺查询 Skill

## 何时使用
用户要：找店、推荐店、按条件筛选店、按距离找店、看店铺团购、店铺排行榜。（店铺评价/探店笔记属 content 技能，Planner 应一并规划）

## 工具决策
| 用户需求 | 工具 | 说明 |
|---|---|---|
| 具体店名 | `searchShop(name)` | 拿 shopId |
| 附近/几公里 | `geoSearch` | 按定位距离 |
| 筛选/排行（评分/人均/细分/设施） | `searchShops(...)` | 服务端过滤 |
| 推荐/哪家好/性价比 | `recommendShops` | ≤5 家、带理由 |
| 团购 | `listShopVouchers(shopId)` | 先搜店拿 id |

**类型映射**：调用 `geoSearch`/`searchShops` 前先读 `references/shop-types.md` 确认 typeId（如 KTV=2、酒吧=8、轰趴桌游剧本杀=9）；**未收录类型（电影院/密室/棋牌等）没有对应 typeId，禁止猜数字传给 geoSearch（必然报"商家类型ID无效"）——改用 `searchShops(name="关键词")` 按名称搜索且不传 typeId**。

## 流程
1. **选工具**：具体店名 → `searchShop(name)`；附近/几公里 → `geoSearch`；筛选/排行 → `searchShops`；推荐/哪家好/性价比 → `recommendShops`。
2. 需要 shopId 的工具（团购）先搜店拿 id。
3. **涉及店铺的回答必须实时调用工具**：即使上下文/历史有类似店，也要重新 searchShops/searchShop/recommendShops 取最新数据，禁止凭历史复述。推荐场景用 `recommendShops` 收口，查询场景用 searchShops/searchShop。
4. **回答与卡片**：涉及店铺时**正文不重复评分/人均/距离/理由**（卡片已含这些），只写店名 + 一句简短点评。**在输出最终回答前调用 `showCards` 声明要展示的店铺卡片**（shopIds=工具结果里这些店的 id 字段值，禁止编造）；回答文本不要输出任何标记或 id——卡片由系统按声明渲染。可以用 Markdown 排版（加粗/列表/换行），前端已支持渲染。
5. 需要按菜系/细分过滤时，读取 `references/food-categories.md` 的映射（如火锅→火锅、日料→异域料理），归入美食类目。
6. 空结果/不匹配 → 换条件重查（放宽评分/换关键词/换细分），不轻易"没有"。
7. 多家店需选择 → `askUserToChoose`（选项 value 用店名）。

## 护栏
- searchShops 只传用户明确提到的条件；用户没提地区就不传 districtId（工具按当前定位过滤，禁止猜）。
- 写操作（取号/下单）必须用户确认。
- 不编造数据；不暴露内部 ID / SQL / 表名 / 工具名。

## 回答规则（Answer 阶段）——卡片展示

- 回答涉及具体店铺（推荐 / 查询 / 列举 / 比较 / 单店详情 / 搜索命中）时，**店铺卡片由系统渲染**（Agent 决策阶段已通过 `showCards` 声明）——回答文本**不要输出任何标记、编号、占位符或 id**（如 `[[...]]`、`[1]`、`（编号 123）` 都不需要）。
- 正文只写**店名 + 一句亮点**（评分/人均/招牌菜/距离/特色标签等 2-3 个），不重复卡片全部字段。
- 即使上下文历史回答没有卡片，本次涉及店铺的回答照常写店名即可（卡片由系统按 showCards 声明渲染，历史风格不影响）。
