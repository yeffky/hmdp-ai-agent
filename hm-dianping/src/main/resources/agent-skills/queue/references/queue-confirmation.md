# 确认提示怎么写（取号 / 取消排队）

> **作用域**：本模板仅供 Agent **决策阶段**在写操作挂起前输出说明文字时参考。
> **系统确认卡片已生成时（调用写工具后自动挂起），Answer 阶段不得再输出任何"确认取号吗/需要确认吗/回复确认"类文字**——
> 确认交互由前端确认卡片 + 确认/取消按钮完成，Answer 只需复述执行结果（成功/失败）。输出二次确认文字会造成"确认两遍"（真实事故）。

写操作确认提示要**让用户一眼看清要确认什么、且全部数字来自真实工具结果**。编造的桌数/等位时长用户当场就能识破，一旦发现一次假的，后面所有提示都不再可信——这是 Agent 失去信任最快的方式，务必只在有真实数据时才写数字。

## 确认卡片（前端渲染，系统生成）

写操作挂起时，系统按以下规范生成**确认卡片**（非 LLM 文本，LLM 只负责把写操作参数调对）：

- **取号卡片** `kind=queue`：
  - `shopName` = 店名（取号参数 `shopId` 查真实店铺）
  - `peopleCount` = 用餐人数（未指定默认 2）
- **取消排队卡片** `kind=queue-cancel`：展示**当前用户的真实排队状况**（系统按登录用户查询最新排队中记录，不依赖 LLM 传参）：
  - `shopName` = 排队店铺名
  - `queueNumber` = 排队号
  - `peopleCount` = 用餐人数
  - `status` = 当前状态（排队中/已叫号）
  - 无排队记录时卡片提示「当前没有排队中的记录」
- 按钮固定「确认 / 取消」；用户点「确认」才执行，改主意 / 新话题由系统判断。
- 卡片数据必须来自真实店铺/排队数据，**禁止编造店名与排队号**；`shopId`/`ticketId` 是内部标识，只用于查库，不展示给用户。

## 取号确认（LLM 文字补充，可选）
- 引用 `queryShopQueueStatus(shopId)` 返回的真实排队情况（当前排队桌数、预计等位时长）。
- 结构：**店名 + 人数 + 真实排队情况**。例：「当前在【店名】有 5 桌在等位，预计等位约 20 分钟。确认取号吗？（回复"确认"即取号，或告诉我修改人数/取消）」
- 若排队情况未查到：**不写数字**，只确认基本信息：「当前在【店名】排队，2 人。确认取号吗？」

## 取消排队确认
- 引用 `queryMyQueueStatus()` 返回的真实排队记录（哪家店 / 排队号 / 人数）。
- 结构：**店 + 排队号 + 人数**。例：「当前在【店名】排队，排队号 12 号，2 人。确认取消排队吗？（回复"确认"即取消）」
- 无排队记录时如实告知「您当前没有排队」，不编造。

## 红线（每一条都是信任问题）
- **禁止凭空编造「约15桌/等位30分钟」这类数字**——只能来自工具真实结果，未查到就不写。
- 店名用工具结果的 `name` 字段，**禁止输出 shopId**（shopId 是对外混淆 ID 短串，也是内部标识，用户看到只会困惑；数据库真实 ID 一律不对外）。
- 不改写用户的人数/店铺：用户说 4 人就是 4 人，说改店就改店。
